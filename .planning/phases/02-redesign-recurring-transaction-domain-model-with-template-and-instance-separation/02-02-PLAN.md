**A. Create `FinanceTracker.Infrastructure/Persistence/Configurations/RecurringTransactionConfiguration.cs`** (per D-01, D-02):

```csharp
using FinanceTracker.Domain.Entities;
using Microsoft.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore.Metadata.Builders;

namespace FinanceTracker.Infrastructure.Persistence.Configurations
{
    public class RecurringTransactionConfiguration : IEntityTypeConfiguration<RecurringTransaction>
    {
        public void Configure(EntityTypeBuilder<RecurringTransaction> builder)
        {
            builder.HasKey(e => e.Id);

            builder.Property(e => e.Name)
                .IsRequired()
                .HasMaxLength(250);

            builder.Property(e => e.Description)
                .HasMaxLength(500);

            builder.Property(e => e.DefaultAmount)
                .IsRequired()
                .HasPrecision(18, 2);

            builder.Property(e => e.StartDate)
                .IsRequired();

            builder.Property(e => e.NextOccurrenceDate)
                .IsRequired();

            builder.Property(e => e.Status)
                .IsRequired()
                .HasConversion<string>();

            builder.Property(e => e.CreatedAt)
                .IsRequired();

            builder.HasOne(e => e.Category)
                .WithMany(c => c.RecurringTransactions)
                .HasForeignKey(e => e.CategoryId)
                .OnDelete(DeleteBehavior.Restrict);

            builder.HasOne(e => e.Frequency)
                .WithMany(f => f.RecurringTransactions)
                .HasForeignKey(e => e.FrequencyId)
                .OnDelete(DeleteBehavior.Restrict);

            builder.HasMany(e => e.Transactions)
                .WithOne(t => t.RecurringTransaction)
                .HasForeignKey(t => t.RecurringTransactionId)
                .OnDelete(DeleteBehavior.SetNull);

            builder.HasIndex(e => e.CategoryId);
            builder.HasIndex(e => e.FrequencyId);
            builder.HasIndex(e => e.Status);
        }
    }
}
```

CRITICAL (Pitfall 1): The `HasMany(...).WithOne(...)` relationship between RecurringTransaction and Transaction is configured HERE and ONLY HERE. Do NOT add a `HasOne(t => t.RecurringTransaction).WithMany(...)` call to TransactionConfiguration — that would create a duplicate relationship and cause EF model validation errors.

**Step 2: Verify the generated migration looks correct before editing.**

The generated `Up()` method should contain (in this approximate order):
1. `DropForeignKey` for the `FrequencyId` FK on Transactions
2. `DropIndex` for `IX_Transactions_FrequencyId`
3. `CreateTable` for `RecurringTransactions`
4. `AddColumn` for `RecurringTransactionId` on Transactions
5. `AddForeignKey` for `RecurringTransactionId`
6. Various indexes

If the generated migration contains unexpected tables or columns unrelated to this phase, STOP and investigate before proceeding.

**Step 3: Manually add the data-nulling SQL statement as the very first statement in `Up()` (per D-09, Pitfall 5).**

Open the generated migration file. At the very TOP of the `Up()` method body, before any EF-generated DDL, add:

```csharp
protected override void Up(MigrationBuilder migrationBuilder)
{
    // D-09: Null out existing FrequencyId values before dropping the column.
    // Existing transactions become standalone (no recurring template).
    migrationBuilder.Sql(
        "UPDATE [Transactions] SET [FrequencyId] = NULL WHERE [FrequencyId] IS NOT NULL");

    // ... EF Core auto-generated DDL follows below (do not modify) ...
```

CRITICAL (Pitfall 5): This SQL must be the FIRST call in `Up()`. EF Core's generated code drops the FK constraint first, then drops the column — but it does NOT automatically null out the data. If there are rows with non-null FrequencyId, the DROP operations may still succeed (SQL Server allows dropping a FK column with data), but the migration intent per D-09 requires data to be nulled before the column is removed.

**Step 4: Update the Down() method with a comment.**

In `Down()`, add a comment before the generated code:
```csharp
protected override void Down(MigrationBuilder migrationBuilder)
{
    // Note: FrequencyId values cannot be restored — Down() reverts schema only.
    // ... EF Core auto-generated DDL follows ...
```

Do NOT add any data restoration SQL to `Down()`.
