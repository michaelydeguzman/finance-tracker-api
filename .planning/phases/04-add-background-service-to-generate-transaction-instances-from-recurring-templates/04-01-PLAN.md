**File 2: RecurringTransactionRepository.cs**
```csharp
using FinanceTracker.Domain.Entities;
using Microsoft.EntityFrameworkCore;

namespace FinanceTracker.Infrastructure.Persistence;

public class RecurringTransactionRepository : IRecurringTransactionRepository
{
    private readonly FinanceTrackerContext _context;

    public RecurringTransactionRepository(FinanceTrackerContext context)
        => _context = context;

    public Task<List<RecurringTransaction>> GetActiveOverdueAsync(DateTime asOf)
        => _context.RecurringTransactions
            .Include(r => r.Frequency)
            .Include(r => r.Category)
            .Where(r => r.Status == RecurringTransactionStatus.Active
                     && r.NextOccurrenceDate <= asOf)
            .ToListAsync();
}
```

Critical rules enforced:
- NO `.AsNoTracking()` — the generation service mutates `NextOccurrenceDate` and must have EF change tracking active to persist updates via `SaveChangesAsync()` (per RESEARCH.md Pitfall 2)
- `.Include(r => r.Frequency)` is MANDATORY — `RecurrenceCalculator.NextOccurrence` needs `template.Frequency.Type` and `template.Frequency.IntervalDays`; without it, NullReferenceException at runtime (per RESEARCH.md Pitfall 1)
- `.Include(r => r.Category)` is included to have the nav prop available; generated Transactions will set `CategoryId` only (not the nav property) to avoid required-nav-property issues on insert (per RESEARCH.md Pitfall 5)
- Filter: `Status == Active AND NextOccurrenceDate <= asOf` per D-05 + D-06

**Step 5: Create FinanceTracker.Worker/Program.cs**
```csharp
using FinanceTracker.Infrastructure.Persistence;
using FinanceTracker.Worker.Services;
using Microsoft.EntityFrameworkCore;
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Hosting;

var host = Host.CreateDefaultBuilder(args)
    .ConfigureServices((context, services) =>
    {
        services.AddDbContext<FinanceTrackerContext>(options =>
            options.UseSqlServer(
                context.Configuration.GetConnectionString("FinanceTrackerDB")));

        services.AddScoped<IRecurringTransactionRepository, RecurringTransactionRepository>();
        services.AddScoped<TransactionGenerationService>();
    })
    .Build();

using var scope = host.Services.CreateScope();
var generator = scope.ServiceProvider.GetRequiredService<TransactionGenerationService>();
await generator.RunAsync();
```

Note: The pattern `using var scope = host.Services.CreateScope()` followed by `scope.ServiceProvider.GetRequiredService<T>()` is the standard way to resolve scoped services from a console app built with `Host.CreateDefaultBuilder`. This ensures `FinanceTrackerContext` (scoped) is properly disposed after the run.
